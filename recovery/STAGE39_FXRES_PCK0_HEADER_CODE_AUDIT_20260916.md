## 실제 바이너리 기계어에서 확인한 읽기 위치
- `fxres.exe`는 PE32+ x86-64, 이미지 베이스 `0x140000000`, SHA-256 `07ae76288148132995538488f12e2214fbecfdc0f18bdc2dd3189093e3e9fa9c`이다. `objdump -D -M intel`에서 다음 주소의 실제 명령어를 확인했고, 새 도구는 해당 위치의 **정확한 명령 바이트 13개 구간**을 검사한다.
- `0x14000da21`: 메모리와 즉시값 `0x304b4350` (`PCK0`) 비교. `0x14000da80`/`0x14000da85`: 처음 읽은 2바이트를 참조하고 `0x0f`를 뺀다. 이어 `0x14000dade`는 길이에서 2를 뺀 만큼 헤더 나머지를 읽도록 버퍼 주소를 잡는다. 따라서 이 코드 경로에서 파일 오프셋 `0x04`의 `0x000f`는 **기본 헤더 레코드의 총 길이 15**로 사용된다. 이것을 게임 버전 15로 단정하지 않는다.
- 레코드는 파일 오프셋 `0x04`부터이며, `0x14000db30`은 관찰된 길이-15 레코드의 끝 바이트가 NUL인지 확인한다. `0x14000dbbb`는 레코드 `+0x06`의 32비트 수를 읽고 `0x14000dbc3`은 `0x100000`과 비교한다. 이 값은 이후 `0x14000dcaa`의 엔트리 반복에 사용된다. 관찰된 파일 오프셋은 `0x0a`이며 아래 표에서는 **선언된 엔트리 수**로 표기한다.
- `0x14000db72`는 레코드 `+0x0a`의 32비트 수를 읽고, `0x14000db7a`에서는 `레코드 길이+4`와 비교하며, `0x14000dc04`~`0x14000dc0a`는 해당 수에서 `레코드 길이+4`를 뺀 만큼을 인덱스 버퍼 길이로 사용한다. 관찰된 파일 오프셋 `0x0e` 값은 **인덱스 끝 오프셋(배타적)**으로 판독한다. 인덱스 시작은 `4+15=19`다.
- 파일 오프셋 `0x06`의 32비트 필드는 `0x14000deeb`에서 읽히지만, 의미는 **알 수 없음**으로 남긴다. 인덱스 해독 방식, 파일별 레코드 레이아웃, 압축·암호화 방법은 이 헤더 판독만으로 확정하지 않았다.
