## First confirmed user-side startup failure and DB risk

- `cmd/protocol-probe/runtime_paths.go` prefers `NINEYIN_SERVER_ROOT`, then executable/CWD ancestors. Nested `9yin-go-server1/9yin-go-server1` is not inherently a root-path error: inspect the location of `resources/modern/share` and the launcher.
- `cmd/protocol-probe/zz_recovered_overlay.go` requires `resources/modern/share/ini/effect/playerweapon` to load equipment; the 2026-09-18 user log showed this fatal missing directory **before** either listener started. Missing `resources/modern/share/map/path` was a nonfatal NPC patrol fallback, not that initial cause.
- `cmd/protocol-probe/skill_catalog.go` eagerly loads mandatory skill and action INIs at package initialization, **before** `main` or either listener. Merely restoring `playerweapon` cannot guarantee startup.
- `cmd/protocol-probe/main.go` uses legacy JSON when `NINEYIN_MYSQL_DSN` is unset. With a configured MySQL DSN, `migrations.Runner.Up` runs before item/equipment/string/drop loader calls. Without `NINEYIN_ALLOW_SCHEMA_MIGRATIONS=YES`, source `migrations/runner.go` now invokes read-only `VerifyApplied`: it SELECTs migration versions/checksums from existing `schema_migrations` and fails closed if missing/drifted. This does not prove actual user DB schema/data compatibility. With explicit `YES`, original potentially mutating migrations still run before catalog loading. Do not authorize them against the user's DB without separate SQL/schema review, backup and explicit approval.
